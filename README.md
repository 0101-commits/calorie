# 프로틴레이더 (Protein Radar)

> 편의점·외식 프랜차이즈·마트 제품의 단백질 가성비와 영양을 검증하고, 1끼 단품·조합을 추천하는 웹 서비스
> **기준 문서:** 프로틴레이더 PRD v1.1(2026-09-15) + 고도화 기획안 v2.0(2026-09-16)

라이브: https://0101-commits.github.io/calorie/

---

## 이 서비스의 규칙 3가지

구현에서 가장 중요한 것은 지표 산식이 아니라 아래 3가지다. 코드를 고칠 때 이 규칙을 먼저 본다.

**1. 모르는 값은 0이 아니다.**
모든 영양 필드는 값과 상태(`*_status`)를 따로 갖는다 — `measured` / `estimated` / `unknown`.
`unknown`은 페널티 면제가 아니라 **등급 보류**(`grade_eligible = false`)로 이어진다.
카드에는 등급 대신 `?`가 뜨고, 어떤 값이 없어서 보류했는지 상세에 적는다.
(v1에서는 나트륨·당류·포화지방을 0으로 채운 59건이 페널티를 전부 면제받아 지방 42g 버거가 A등급을 받았다.)

**2. 판정은 빌드가 한 번만 한다.**
지표·등급·워싱·CleanRadar 모두 `scripts/build.js`에서 계산해 `data.json`에 저장한다.
화면은 저장된 값을 **읽기만** 한다. 런타임에 다시 계산하지 않는다.
룰은 `rules/rule_v1.1.json`이 단일 원천이고, 코드의 `DEFAULT_RULES`는 테스트 픽스처다.
둘이 갈라지면 게이트 G5가 빌드를 실패시킨다.

**3. 근거 없는 판정을 화면에 올리지 않는다.**
원재료를 확보하지 못하면 성분을 추정하지 않고 "원재료 미확보"로 둔다.
성분 사전의 기피(tier 4) 판정에는 공적 근거(`basis`)가 반드시 있어야 하고, 없으면 테스트가 막는다.
제품 이미지는 출처(`image_source`)가 없으면 렌더하지 않는다.

## 지표

| 지표 | 산식 | A등급 | 답하는 질문 |
|---|---|---|---|
| **PPR** | 단백질(g) ÷ (가격 ÷ 1,000) | ≥ 8.0 | 얼마나 싸게? |
| **CPD** | 단백질(g) ÷ (열량 ÷ 100) | ≥ 12.0 | 얼마나 가볍게? (5.5 = 식약처 '고단백' 열량 기준) |
| **NPI** | 단백질 × 원물 Q(1.0~0.6) × (1 − 감점 ≤0.5) + 식이섬유 보너스 | ≥ 25 | 영양 수치로 본 실질 단백질 |
| **CleanRadar** | 원재료 4단계 분류 기반 0~100 | ≥ 75 안심 | 원재료·첨가물은 깨끗한가 |
| **PW** | W1~W6 가점 0~100 | < 25 검증 | '고단백' 표기가 사실인가 |

종합 등급은 PPR·CPD·NPI를 A=4~D=1로 점수화한 평균(컷 3.3/2.3/1.3)이며, 워싱 판정(PW ≥ 50) 시 1단계 강등한다.

> 컷오프 3.3/2.3/1.3은 PRD §1.3 본문의 3.5/2.5/1.5와 다르다. 본문 값은 같은 PRD §1.7의 벤치마크 6건 중 2건과 모순되고, 3.3/2.3/1.3이 6/6 일치한다. 예시표를 정본으로 채택했고 `tests/rules.test.js`가 이 정합성을 고정한다.

## 화면

3탭(홈·랭킹·내 기준) + 바텀시트.

- **홈** — 검색(초성·오타 허용)·스캔·최근 확인분·워싱 주의
- **랭킹** — 비교 기준이 다른 채널을 섞지 않는다
  - `지금 매장에서` 편의점·프랜차이즈 · 1개 판매 단위 가격 기준
  - `미리 쟁여두기` 마트·온라인 · 단백질 100g당 가격 기준
  - 등급 보류 건은 기본 노출에서 빠지고 `정보 부족만` 필터로 볼 수 있다(제보 유입 동선)
- **내 기준** — Mifflin-St Jeor → TDEE → 목적 보정 → 1끼 타깃 → 단품/조합 Top 5
  - 조합은 1끼의 정의를 지킨다: 음료 1개 이하, 식사류 최소 1개, 나트륨 1끼 목표 150% 이하
- **상세** — 「이 등급이 나온 이유」(대입 과정·감점 내역·판정 못 한 항목), 워싱 조항별 배점, 원재료 판정과 근거, 영양표(결측은 `—`), 출처 원본 링크

## 실행

```bash
npm run pipeline   # 격리 → 정규화 → 빌드 (data.json · data_index.json · data_meta.json)
npm test           # 단위 테스트 30건
npm run site       # 공개 배포 산출물 수집(_site) + 배포 위생 게이트 G7
npm run serve      # http://localhost:8080
```

공공DB 수집에는 `.env`의 `DATA_GO_KR_API_KEY`가 필요하다. 코드에 키를 적지 않는다.

## 정책

- 영양정보는 식약처 공공DB, 브랜드 공식 영양정보, 포장 표시사항에서 가져오고 각 카드에 출처·확인일·룰 버전을 적는다
- 체형 정보는 브라우저에만 저장하고 서버로 보내지 않는다(비회원제)
- 편의점 앱·로그인 뒤 데이터·타사 식단 DB는 어떤 단계에서도 수집하지 않는다
- 본 서비스는 정보 제공 목적이며 의학적 조언을 대신하지 않는다
